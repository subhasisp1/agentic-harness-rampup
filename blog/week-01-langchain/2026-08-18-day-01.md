# INVOKE THE LLM :

The first step is to get familar with invoking llms: both locally and servers( via openrouter ).I used both ways:invoke qwen2.5vl:32b via Ollama ( local llm runner ),
and via openrouter-api ( model name : anthropic/claude-haiku-4.5 ). Hardware used for local inference was RTX 5090, which showed the OOM error while running the local llm.
After debugging it was found out that , ollama's default 32k context add an 8gb KV cache on top of the models 21 gb weights, so reducing the context to  8192 worked fine 
for the mentioned hardware.For the upcoming invokes I have decided to keep openrouter api inference , which fress us from such OOM errors.


# OUTPUT FROM INVOKING :

When you invoke a llm with a question , what comes back is a list of role-tagges mesaages ( 'system', 'human', 'AI' ) plus toekn usage and other metadata. 


# TEMPLATES AND CHAINS :

'ChatPromptTemplate' with '{variables}' in it are resuable prompts that can be given to the LLM while invoking ( something useful while preparing the system message ).
"to_messages()" object of ChatPromptTemplate allows us to inspect all types of message before sending it to llm. 
The chain building is as simple as an one line code : "1st runnable" | "2nd runnable " | "3rd runnable" ....(Runnables are abstract functions that will have the same format of returns, so every runnables output can be input to another runnable ). | is a LCEl ( Langchain Expression Language ). 

Once the chain is built , you can call it multiple times ( so chains are reusable ).
