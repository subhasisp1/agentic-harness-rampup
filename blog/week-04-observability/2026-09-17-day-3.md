# Week 4, Day 3 (Thu): 

## Goal :
Yesterday's numbers vanished when the script ended. So today we keep the traces.
Two SQLite tables keep the runs, which turns that into what this run cost compared with the last one. 

## Concept takeaways :
- Two SQLite tables. `runs` holds one row per run: a label, when it started, the seconds, the tokens
  and the cost. `spans` holds one row per span, tied to its run. The run id is just the root
  span's id, so nothing new has to be invented to key them.
- `INSERT OR REPLACE` makes saving the same run twice harmless. Without it a script that saves
  in a loop quietly doubles its own history.
- The point is the comparison, not the storage. One run answers "what did this cost". Two
  hundred runs answer "is this more expensive than it was last week", which is the question
  that actually matters when I change a prompt.

## What went wrong or took time :
- I first stored the raw nanosecond timestamps for every span and nothing else. Reading them
  back meant doing the subtraction again in SQL, so the table now stores the duration in
  milliseconds directly.


## Takeaways :
- Two identical questions do not cost the same, so a single measurement is not universal/generic.
