# Week 4, Day 2 (Wed): 

## Goal :
Today we will read `usage_metadata` off every model reply, hang the token counts
on the spans, and put a price table next to them so a run reports its cost.


## Concept takeaways :
- Every model reply carries `usage_metadata` with `input_tokens` and `output_tokens`. It arrives
  on the `LLMResult` in `on_llm_end`, so the tracer writes it onto the span it already opened.
  Some providers put the counts in `llm_output["token_usage"]` instead, so `_usage` checks both
  and returns zeros rather than guessing.
- The price table is two numbers per model: dollars per million tokens in, and out. I checked the
  live OpenRouter catalogue. Haiku 4.5( the one we are using now ) is $1 in and $5 out. Output costs five times input.
- `by_node()` walks a model span up its parents until the next step would be the root, so every
  model call is attributed to the node that made it. That is the split I wanted, because the
  router is a second model call on every turn, including the ones that just say hello.


## What the live run showed :
One notes question: $0.005159, 4,184 input tokens against 195 output. The input count climbs
every lap of the tool loop, 314 then 1,157 then 1,315 then 1,398, because each lap resends the
whole message list with one more tool result in it. The router is 37% of the wall clock and
about 7% of the cost.



## Takeaways :
- The tool loop is the expensive path, and it gets more expensive with every lap.
- The router buys a cheaper chat path and charges a model call per turn for it.
