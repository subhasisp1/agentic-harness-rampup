# Week 3, Day 5 (Fri): servers.json, the CLI, ship

Today's goal is to move the server list and the policy out of code into `servers.json`, wrap the CLI on
top (threads, budget, SQLite memory, paused-run recovery), ship the week.


## Concepts, in plain words
- servers.json is one of the harness's important file: which processes to start, which tools need a human.
  Adding a capability or revoking trust is an edit there, not a code change. This makes it easily configurable.
- The async checkpointer: `AsyncSqliteSaver.from_conn_string(path)` is an async context
  manager; under `ainvoke` the graph calls its async methods, so state reads become
  `await toolbelt.aget_state(config)`. Otherwise identical to week 2's SqliteSaver: same
  file, same threads, same checkpoints.
- Paused-run recovery carried over from week 2 unchanged in shape: on startup, if
  `saved.next` is set, the pending interrupt from `saved.tasks[0].interrupts` is asked first
  and resumed with `Command(resume=...)`, only then the prompt reads new input.


## Takeaways
- The deliverable is structurally a small real harness now: a loop, a config file of tool
  servers, a permission policy, persistent conversations.
- Week 1 imported tools, week 2 owned the loop, week 3 moved the tools behind a protocol and
  the trust into a table. Prompt -> loop -> memory -> constraints, each one now explicit.
