Yesterday's state had only the message list. Today I will add more fields, a router node that goes in front of the model, and the guardrail

# THE STATE FIELDS :

```python
class State(TypedDict):
    messages: Annotated[list[AnyMessage], add_messages]
    mode: str
    tool_calls_made: Annotated[int, operator.add]
    max_tool_calls: int
```

Three fields,`mode` is a plain field : last write decides the execution status of loop. `tool_calls_made` has a reducer : a node returns an increment and LangGraph
adds it, and it starts at 0 without anyone setting it. `max_tool_calls` is passed in the input of every run, the way `recursion_limit` was passed per
invoke last week. One catch I found while testing : a plain field that no node has written yet is absent from the state dict, not `None`.In our case, max_tool_calls was 
that node. So the budget check reads it with `state.get("max_tool_calls", MAX_TOOL_CALLS)`.

# THE ROUTER :

The router is a model call the user never sees. It is `llm.with_structured_output(Route)`, where `Route.mode` is
`Literal["chat", "tools", "json"]`, so pydantic rejects any other word. The node writes `mode` into the state, and the edge function only reads it :

```python
def router(state: State) -> State:
    decision = router_llm.invoke([ROUTER_SYSTEM, state["messages"][-1]])
    return {"mode": decision.mode}


builder.add_conditional_edges(
    "router", by_mode, {"chat": "chat", "tools": "model", "json": "json_answer"}
)
```

The dict at the end is the decision,i.e a node table.The node does the work and records it in the state, the edge reads the
state and names the next node.

Three ways, one `get_llm()`. `chat` is the plain model without tools ( no tool schemas are sent, so it is cheaper ). `model` + `tools` is yesterday's
loop. `json_answer` is `with_structured_output(Answer)` with an `answer` and a `confidence` between 0 and 1, the structured output . It stores the result as an `AIMessage` 
whose content is the JSON string, so the conversation stays a message list.

# THE BUDGET(A GUARDRAIL):

The tool node now returns `{"tool_calls_made": len(results)}` along with the tool messages. The edge after the model has three answers : no tool
calls → END , calls made < budget → tools ; otherwise → `stop`. The stop node answers every pending tool call with a `ToolMessage` saying the budget is
spent,so the run ends. Why a ToolMessage and not plain text ? Because the API wants a result for every tool call, or the next model call fails. `recursion_limit` is not passed any more as
LangGraph's default of 25 stays as the limit.
